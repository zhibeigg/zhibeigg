## 关于我

你好，我是纸杯。

主要使用 **Kotlin、Java 和 TypeScript**，长期开发 Minecraft 服务端插件、跨服通信、JVM 后端与业务工具。比起堆叠技术名词，我更在意系统是否清晰、稳定，并且经得起长期维护。

## 代表项目

- **[Orryx](https://github.com/zhibeigg/Orryx)** — 面向 Bukkit / Paper 的技能系统，支持复杂逻辑、配置表达与扩展 API。
- **[Nodens](https://github.com/zhibeigg/Nodens)** — 属性与公式引擎，提供物品模板和 PRD 伪随机等玩法基础能力。
- **[RedisChannel](https://github.com/zhibeigg/RedisChannel)** — 基于 Lettuce 的 Bukkit Redis 通道，用于跨服消息与事件同步。
- **[Azathoth](https://github.com/MinecraftAzathoth/azathoth)** — 模块化 Minecraft MMORPG 服务框架，探索 Ktor、gRPC、事件通信与弹性部署。
- **[LLM-BRAIN](https://github.com/zhibeigg/LLM-BRAIN)** — 基于有向记忆图和多角色协作的 LLM Agent 实验项目。

## 关注方向

## 工程习惯

- 保持接口小而明确，避免无意义的抽象。
- 优先保证稳定性、可观测性与可维护性。
- 把文档、示例和迁移成本视为功能的一部分。
